Create knowledge/variable_graph.py with class VariableGraph that manages ONE FalkorDB graph for ONE feedback variable.

**Constructor:** `__init__(self, variable_name: str, precision: float, db=None)`
- variable_name: e.g. "speed", "pos_x", "yaw"
- precision: minimum delta from bin discovery (used as discretization resolution)
- db: FalkorDB instance (optional -- if None, graph operations are no-ops returning False)

**Graph naming:** Each variable gets its own FalkorDB graph via `db.select_graph(f"kg_{variable_name}")`. This means speed gets graph "kg_speed", pos_x gets graph "kg_pos_x", etc.

**Node model:** Nodes have label `:State` with properties:
- `value`: the discretized state value (float, rounded to precision)
- `variable`: the variable name (string, for self-documentation)

Nodes are created with MERGE on `value` to prevent duplicates:
```cypher
MERGE (s:State {value: $discretized_value})
ON CREATE SET s.variable = $variable_name
```

**Edge model:** Edges have label `:ACTION_BIN` with properties:
- `bin_id`: integer bin identifier from Phase A results
- `bin_label`: string label (e.g. "ON", "DEAD_ZONE", "LEFT_BIN_50")
- `action_name`: which action caused this transition (e.g. "gas", "brake", "left")

Edges are created with CREATE (not MERGE -- same action bin between same nodes in different frames is a valid repeat):
```cypher
MATCH (from:State {value: $from_value})
MATCH (to:State {value: $to_value})
CREATE (from)-[:ACTION_BIN {bin_id: $bid, bin_label: $blabel, action_name: $aname}]->(to)
```

**Discretization:** Implement discretization as an inline static method or module-level function directly in this file. Do NOT import round_to_resolution from knowledge_manager -- it is an instance method on KnowledgeManager (line 749), not a module-level function, so importing it would fail with ImportError. The math is trivial (3 lines, no instance state):

```python
@staticmethod
def _discretize(value: float, min_delta: float, precision: int = 7) -> float:
    """Round a state value to the knowledge graph resolution.
    Same math as KnowledgeManager.round_to_resolution but standalone."""
    if min_delta > 0:
        value = round(value / min_delta) * min_delta
    return round(value, precision)
```

Use `self._discretize(value, self.precision)` in all methods that need discretization.

**Public methods:**
1. `connect(host, port) -> bool` -- Select the named graph from FalkorDB
2. `record_transition(from_value: float, to_value: float, bin_id: int, bin_label: str, action_name: str) -> bool` -- Discretize both values, MERGE nodes, CREATE edge
3. `get_node(value: float) -> Optional[Dict]` -- Discretize value, MATCH node, return properties
4. `get_edges_from(value: float) -> List[Dict]` -- Get all outgoing ACTION_BIN edges from a discretized node
5. `get_edges_to(value: float) -> List[Dict]` -- Get all incoming edges
6. `count_nodes() -> int` -- Count State nodes in this graph
7. `count_edges() -> int` -- Count ACTION_BIN edges
8. `reset() -> bool` -- Delete all nodes and edges in this graph
9. `is_connected() -> bool`

**Important:** Do NOT import or depend on TMNFAdapter, FrameOrchestrator, KnowledgeManager, or any adapter. This is pure graph operations. Only imports: logging, typing. Discretization is self-contained.

Create knowledge/multi_graph_manager.py with class MultiGraphManager that coordinates multiple VariableGraph instances for simultaneous per-frame recording.

**Constructor:** `__init__(self, variables: Dict[str, float], bins_by_action: Dict[str, list])`
- variables: mapping of variable_name -> precision (e.g. {"speed": 0.6, "pos_x": 0.001, "yaw": 0.001})
- bins_by_action: mapping of action_name -> list of bin dicts (from Phase A results)
  Each bin dict has keys: bin_id, min, max, label, effect_delta (or effect_mean)

**CRITICAL: Bin dict format.** bins_by_action expects dicts with keys 'min' and 'max' (NOT 'a_min'/'a_max'). This is the format produced by `ActionBin.to_dict()` from intelligence_experimentation.py. If ActionBin dataclass objects are passed instead of dicts, convert them first via `[b.to_dict() for b in bins]`. Document this in the docstring.

The canonical bin dict format used by MultiGraphManager:
```python
{"bin_id": 0, "min": 0.0, "max": 0.001, "label": "DEAD_ZONE", "effect_delta": 0.0}
```
This matches ActionBin.to_dict() output and KnowledgeManager.resolve_bin() expectations.

Internally creates one VariableGraph per variable.

**Bin resolution:** Include a `resolve_bin(action_name: str, value: float) -> Optional[Dict]` method (copy the logic from KnowledgeManager.resolve_bin -- find which bin contains the given value). The method uses dict keys 'min' and 'max' for bin boundaries.

**Public methods:**

1. `connect(host='localhost', port=6379) -> bool` -- Connect all VariableGraph instances. Returns True only if ALL connect.

2. `record_frame(from_feedbacks: Dict[str, float], to_feedbacks: Dict[str, float], action: Dict[str, float]) -> bool` -- The core method. For each variable in self.variables:
   a. Extract from_value = from_feedbacks[variable_name], to_value = to_feedbacks[variable_name]
   b. For each action in the action dict, resolve to bin
   c. Call variable_graph.record_transition(from_value, to_value, bin.bin_id, bin.label, action_name)

   This records one transition per variable per action (GRAPH-06: all graphs update simultaneously, GRAPH-10: one node per graph with action edge).

   Skip variables not present in feedbacks (graceful -- not all adapters report all variables).
   Skip actions with value 0.0 and bin_id 0 (dead zone -- D0 is a real action but the dead-zone bin doesn't cause meaningful transitions in the graph; the node simply stays at its current value, which is already represented by the existing node).

3. `get_variable_graph(variable_name: str) -> Optional[VariableGraph]` -- Return specific graph for queries

4. `get_all_stats() -> Dict[str, Dict]` -- Return node/edge counts per variable

5. `reset_all() -> bool` -- Reset all variable graphs

6. `is_connected() -> bool` -- True if all graphs connected

**Important:** The action dict from TMNF has keys: gas, brake, left, right. For each non-zero action, resolve its bin and record the transition in ALL variable graphs. The same frame produces one edge per active action per variable graph.

For the 4 binary TMNF inputs, bins_by_action looks like:
```python
{
    "gas": [{"bin_id": 0, "min": 0.0, "max": 0.001, "label": "DEAD_ZONE"},
            {"bin_id": 1, "min": 0.001, "max": 1.0, "label": "ON"}],
    "brake": [{"bin_id": 0, ...}, {"bin_id": 1, ...}],
    "left": [{"bin_id": 0, ...}, {"bin_id": 1, ...}],
    "right": [{"bin_id": 0, ...}, {"bin_id": 1, ...}],
}
```
