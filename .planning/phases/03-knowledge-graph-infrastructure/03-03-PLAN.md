Create intelligence/multiplicity_tester.py with class MultiplicityTester that probes intermediate action values to validate bin completeness.

**Imports:** Use ActionBin from intelligence.intelligence_experimentation. Use standard logging, typing, dataclasses.

**Data classes:**

```python
@dataclass
class MultiplicityProbe:
    """Result of probing one intermediate value."""
    action_name: str
    probe_value: float        # The intermediate value tested
    delta: float              # State change observed
    nearest_bin: ActionBin    # Which existing bin this delta matches
    is_new_bin: bool          # True if delta doesn't match any existing bin
    tolerance: float          # Tolerance used for matching

@dataclass
class MultiplicityResult:
    """Full result of multiplicity testing for one action."""
    action_name: str
    existing_bins: List[ActionBin]
    probes: List[MultiplicityProbe]
    new_bins_found: int       # Count of intermediates that don't match existing bins
    validated: bool           # True if no new bins found (existing bins are complete)
```

**Constructor:** `__init__(self, adapter, bins_by_action: Dict[str, List[ActionBin]], feedback_variable: str = 'speed')`
- adapter: any adapter with save_state(), rewind(), send_action_dict(), wait_one_tick(), get_feedbacks()
- bins_by_action: discovered bins from Phase A as Dict mapping action name to list of ActionBin DATACLASS objects (NOT dicts). MultiplicityTester works with ActionBin objects because it accesses `.a_min`, `.a_max`, `.effect_delta` attributes directly. This is intentional -- MultiplicityTester sits at the intelligence layer alongside ExperimentationIntelligence, which produces ActionBin objects.
- feedback_variable: which variable to measure deltas on (default 'speed')

**Bin format note:** MultiplicityTester uses ActionBin dataclass objects (with `a_min`, `a_max` attributes). MultiGraphManager (Plan 01) uses bin dicts (with `min`, `max` keys, as produced by `ActionBin.to_dict()`). The conversion boundary is: intelligence layer works with ActionBin objects, knowledge layer works with ActionBin.to_dict() dicts. When passing bins from ExperimentationIntelligence to MultiGraphManager, the caller converts via `[b.to_dict() for b in action_result.discovered_bins]`.

**Core method: test_action(action_name: str, num_intermediates: int = 5) -> MultiplicityResult:**

Algorithm:
1. Get the bins for this action from bins_by_action
2. If only 2 bins (binary input like gas), test midpoints between bin boundaries:
   - Between DEAD_ZONE max (0.001) and ON min (0.001) -- they're the same, so test values like 0.0005, 0.00075, 0.0015, 0.002
   - Actually for binary inputs where MIN == MAX (or very close), generate test points:
     a. Below MIN: min/2, min/4 (should be dead zone)
     b. Above MIN: min*2, min*10, 0.5 (should be ON, same delta as max)
     c. Between 0 and MIN: linspace(0, min, num_intermediates)
3. If many bins (analog input), test midpoints between adjacent bins:
   - For each pair of adjacent bins, probe the midpoint value
   - Also probe 1/3 and 2/3 points between bins if num_intermediates > 1
4. For each probe value:
   a. adapter.save_state()
   b. Record feedback_before (get_feedbacks()[feedback_variable])
   c. Send action dict with only this action set to probe_value
   d. wait_one_tick()
   e. Record feedback_after
   f. delta = feedback_after - feedback_before
   g. adapter.rewind()
   h. Compare delta to each existing bin's effect_delta. If within tolerance (default: precision * 0.5), it matches that bin. Otherwise, it's a new bin.

**Method: test_all(num_intermediates: int = 5) -> Dict[str, MultiplicityResult]:**
Run test_action for every action in bins_by_action. Return dict of results.

**Method: _delta_matches_bin(delta: float, bin_delta: float, tolerance: float) -> bool:**
Return abs(delta - bin_delta) <= tolerance. For binary inputs where bin deltas are large (0.6 for gas), a tolerance of 0.1 is appropriate. For analog with fine precision, use smaller tolerance.

**Important design notes:**
- This is a LIVE testing module (requires adapter with rewind). But it can be tested offline with MockAdapter.
- No linearity assumptions. Every intermediate is probed individually.
- "Not doing an action is also an action" -- probing value=0.0 should match the DEAD_ZONE bin's delta (which is delta_0 from Phase A).
- Use the same probe pattern as Phase A: save_state -> apply action -> measure -> rewind.

Create tests/test_multiplicity.py with offline tests using a MockAdapter that simulates binary TMNF inputs.

**MockAdapter for multiplicity testing:**
Extend the pattern from test_frame_orchestrator.py. The mock must support:
- save_state(): stores current speed
- rewind(): restores speed to saved value
- send_action_dict(a): stores pending action
- wait_one_tick(): applies action (gas: +5.0, brake: -3.0, any value above threshold gives same delta)
- get_feedbacks(): returns {'speed': self.speed}

The key behavior: gas value 0.5 produces SAME delta as gas value 1.0 (binary). Gas value 0.0001 (below threshold 0.001) produces NO delta. This simulates TMNF's binary inputs.

```python
class MockMultiplicityAdapter:
    def __init__(self):
        self.speed = 50.0  # Start at non-zero speed
        self.saved_speed = 50.0
        self.last_action = {}

    def save_state(self):
        self.saved_speed = self.speed
        return True

    def rewind(self):
        self.speed = self.saved_speed
        return True

    def send_action_dict(self, action):
        self.last_action = action.copy()
        return True

    def wait_one_tick(self):
        # Binary behavior: any gas > 0.001 gives +5.0, any brake > 0.001 gives -3.0
        if self.last_action.get('gas', 0) > 0.001:
            self.speed += 5.0
        if self.last_action.get('brake', 0) > 0.001:
            self.speed = max(0, self.speed - 3.0)
        # Left/right: tiny yaw effect (but we test on speed, so no effect)

    def get_feedbacks(self):
        return {'speed': self.speed}
```
