Add `self._multi_graph_available = False`

**New method: initialize_multi_graph(host, port) -> bool:**
If self.multi_graph is set, call `self.multi_graph.connect(host, port)`. If successful, set `self._multi_graph_available = True` and return True. Otherwise return False.

**Changes to execute_one_frame:**
After the existing history.append(result) and the existing legacy knowledge graph recording block, add a NEW block for multi-graph recording:

```python
# Record to per-variable knowledge graphs (Phase 3)
if self.multi_graph and self._multi_graph_available:
    try:
        self.multi_graph.record_frame(
            from_feedbacks=feedback_before,
            to_feedbacks=feedback_after,
            action=action
        )
    except Exception as e:
        logger.warning(f"[ORCHESTRATOR] Multi-graph recording failed for frame {self.frame_id}: {e}")
```

**CRITICAL: Do NOT remove or modify the existing legacy recording path.** The old `record_transition_simple()` call via `self.knowledge` must remain for backward compatibility with Phase 2 tests. The two recording paths coexist:
- Legacy path: one monolithic graph with Frame nodes (Phase 2)
- New path: per-variable graphs with State nodes (Phase 3)

**New method: query_variable_graph(variable_name, value) -> Optional[Dict]:**
If multi_graph available, return `self.multi_graph.get_variable_graph(variable_name).get_node(value)`. Otherwise return None. This is an extension of BRAIN-07 (query_frame) for the per-variable model.
